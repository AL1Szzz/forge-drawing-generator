# 新批次使用说明（锻件尺寸图）

> 2026-11-03 定稿。适用于之后所有新批次。
> 一句话：**把批次文件夹准备好 → 拖到 BAT 上 → 核对 manifest 和复核清单 → 完成。**

---

## 一、准备批次文件夹

在 `<批次根目录>\` 下新建文件夹，名字用批次号（如 `批A`），往里放：

| 文件 | 必需性 | 说明 |
|---|---|---|
| 产品图纸 PDF | **必需** | 如 `F25A0001~2085.pdf`，每页一张图纸 |
| 制造大纲 PDF | **必需** | 如 `批A XX单位 A-001.pdf`，用来看红笔批注、取样列、数量 |
| `热处理工艺\*.exb` | 可选 | 热处理报告，文件名含 6 位炉号。**没有 DXF 时会自动直读 exb（结果标"待核"）** |
| `热处理工艺\*.dxf` | 可选 | 用 CAXA「DWG/DXF 批转换器 → 按目录转换」导出的 DXF，**直接放 `热处理工艺\`**（原 exb 挪到 `热处理工艺\exb\`）。**放了 DXF 就用 DXF（正式稿），且方块件/合锻/取样表全自动提取** |

> **热处理卡归各批次自己管**：`热处理工艺\` 建在**每个批次目录里面**（2026-11-03 起，总目录下那份公用的已删除）。换批次时把该批的卡放进自己文件夹，脚本只在本批次目录内查找，不会串批。
>
> **质保号子号口径（2026-11-05）**：质保号拆成 `-1/-2/-3` 子号的，每页图纸都会单独识别。**同尺寸+同批次 → 合一张图，质保号都写在图上、数量求和；尺寸或批次不同 → 分开做**。合并与拆分都会在复核清单"问题"列留痕。

两种典型组合：

- **图纸重量行直接给了锻件尺寸**（如 `Ø320×70×3%=45.1KG`）→ 只需要两个 PDF，尺寸照用、不加余量，出正式稿。
- **要按热处理尺寸加余量** → 最好导一份 DXF 放进去；不导也能跑（EXB 直读），但全部标"待核稿"。

## 二、跑（两种方式任选）

### 方式 A：拖 BAT（推荐，日常用这个）

把整个批次文件夹**拖到** `工作区\工具\一键跑批\一键跑批.bat` 上松手即可。
（或双击 BAT，在窗口里粘贴批次目录路径回车。）

约 1–5 分钟自动完成：建清单（缺才 OCR）→ 读热处理尺寸（DXF 优先/EXB 直读）→ 出图 → 合并 → 在批次目录生成：

- `<批次>_锻件尺寸图_汇总.pdf` ← **交付物**（首页是复核表）
- `复核清单.md` ← 需人工复核的项一目了然
- `_锻件图\` 里的单张图和 `生成清单.csv`

窗口最后显示"完成"才算成功；中途报错会写明缺什么，补上后**重跑一遍即可**（重跑安全，旧图自动归档，不会混进新汇总）。

### 方式 B：让 WorkBuddy 跑

对话里说一句：**"用锻件图 skill 跑 `<批次根目录>\<批次名>`"**。
规则都固化在 `工作区\b5a9a823\skill\SKILL.md`，不依赖聊天历史。

## 三、跑完必须人工做的两件事（底线）

1. **核对 manifest.csv**——如果它是 OCR 自动建的（之前不存在），**必须逐页目检**图号、炉号、材质、重量行，错了直接改 CSV 再重跑。F25A 新图号系列 OCR 识别率很低，批A 是手工写的清单。
2. **看 复核清单.md**——"需人工复核"表里每一项都要过目；"不出图"的项按提示补数据重跑。

**业务底线：OCR 只出草稿值，无据不猜；尺寸错一个数字就是报废件。**

## 四、特殊情况手工补表（无 DXF 时不会自动生成）

| 情况 | 要建的文件 | 格式（表头） |
|---|---|---|
| 有取样件（大纲"取样"列/图纸"/样XXkg"） | `样件尺寸.csv` | `炉号,形状,取样外径,取样内径,取样长度,取样件数,备注`（样图尺寸=取样行+10，重量行留空） |
| 方块件（三个无Ø尺寸） | `块件尺寸.csv` | `炉号,…,热处理A,热处理B,热处理C,取样A,取样B,取样C,…` |
| 合锻件 | `合锻表.csv` | `炉号,形状,热处理A,热处理C,产品长度,组成件长度` |

参考样例：实际批次目录中的 `样件尺寸.csv`（批A 首次使用时的格式）。
有 DXF 时这三张表全自动生成，不用手写。

## 五、改了数据想重出

直接**再拖一次 BAT**。可以反复跑：
- 改 manifest.csv / 样件尺寸.csv → 重跑，只影响相应图；
- 旧图自动归档到 `_锻件图\_旧稿_时间戳\`，不会混进新汇总 PDF。

## 六、出图规则速查（已定稿，不用再问）

- 尺寸优先级：**① 图纸重量行直给（照用）→ ② 热处理尺寸+余量 → ③ 成品尺寸+余量（待核稿）**
- 余量档：≤1T 补 10 / ≤3T 补 15 / >3T 补 20；方块件每向 +10；圆棒加余量后 Ø<50 抬到 50
- 判型：`Øa/Øb×L` 筒 · `ØD×L`(L≥0.9D) 棒 · `ØD×L`(L<0.9D) 圆饼 · `a×b×c` 方块
- N合1：按合锻后的整棒出一张，规格带 `(5合1)` 后缀，质保号/炉号写一起
- 取样件：图号加"样"，尺寸=大纲取样行+10，重量行留空
- 锻件图不标公差

## 七、常见问题

| 现象 | 处理 |
|---|---|
| BAT 提示"缺少原始图纸 PDF" | 产品图纸 PDF 没放进批次目录或文件名与 manifest 的 pdf 列不一致 |
| 全部"待核稿" | 用的是 EXB 直读（无 DXF）。要正式稿：CAXA 导 DXF 放 `DXF\`，删掉 ht_dims.csv 重跑 |
| OCR 清单乱码/图号空 | 正常现象，手工改 manifest.csv（5-10 页的批次手写最快） |
| 找不到 Python | BAT 已内置路径 `C:\Program Files\Python311\python.exe`，无需配置；换电脑要改 BAT 第 15 行 |

## 八、过程中要不要 AI 参与？

**跑批本身不需要。** 整条链是纯本地 Python 脚本，不调用任何大语言模型、不联网、不上传数据，断网也能跑，同一份输入跑几次结果完全一致：

| 环节 | 靠什么 | 是不是 AI |
|---|---|---|
| 读图纸标题栏 | RapidOCR（本地 ONNX 小模型，只认字） | 本地 OCR 模型，不是生成式 AI |
| 读 exb / DXF 热处理尺寸 | zlib 解压 + 正则解析 / ezdxf | 纯程序 |
| 算尺寸、判形状、定余量 | 已固化的规则表 | 纯程序 |
| 画图、合并 PDF | PyMuPDF 矢量绘图 | 纯程序 |

那些通过多轮对话确定下来的口径（判型、余量档、合锻、取样、圆饼、+10、Ø≥50 等）已经**写进代码和 SKILL.md**，所以"跑"的时候不需要 AI 在场，也不依赖聊天历史。

**但两件事仍需要人（或叫 WorkBuddy 帮忙）：**

1. **审 manifest.csv**：OCR 只出草稿值，图号/炉号/材质/重量行必须逐页目检。**尺寸错一个数字就是报废件**，这一步不能省，小批次手写更快更稳。
2. **遇到没见过的新情况**：新图号系列（如 `F25A0001` 曾让 OCR 全失效）、红笔批注、取样行与图纸样重对不上、卡片只写样件尺寸、特殊合锻…… **脚本只执行已固化的规则，规则之外的不会自己猜**。要么人工定口径后填进 CSV，要么在对话里让 WorkBuddy 读图判断（必要时改代码补新规则），定完再拖 BAT。

一句话：**"跑批"不用 AI，"审图"和"定新口径"要人（可以叫 AI 帮忙）。**

## 九、换一家单位怎么办？

这套工具不是XX单位专用的。换单位分两层：

**① 只换编号规则 → 不用改代码，加一个配置文件**
把 `工作区\b5a9a823\skill\profiles\default.json` 复制一份，按新单位改里面的正则
（图号 `re_draw*`、图纸文件名范围 `re_range`/`re_pdf_name`、炉号 `re_lu*`、材质字典 `materials`、字体路径），
然后**放进那个批次文件夹，命名 `unit_profile.json`**，拖 BAT 时自动生效。字段含义见 `profiles\README.md`。
不放这个文件就用默认的XX单位口径，老批次完全不受影响。

**② 版式/卡片格式不同 → 需要人工适配一次**
这些跟客户的图纸长什么样绑定，改正则解决不了，第一次接新单位时先拿 1~2 张图纸手工走一遍：
- `forge_gen.py` 的图框遮挡坐标、标题栏 6 列位置（按新单位图框重新量）；
- 热处理卡片必须是 **CAXA 电子图板**出的 exb/dxf（解析格式是针对它逆向的）；
- 制造大纲表头列名与列序（`read_qty.py` / `read_liaodan.py`）；
- **余量档、判型、合锻、取样、方块件 +10 属于工艺约定，必须跟新客户确认，不要照搬**。

**③ 换电脑** —— BAT 已改成相对路径找 skill，只需设环境变量 `FORGE_PYTHON` 指向 Python 3.11 的可执行文件
（默认仍是 `C:\Program Files\Python311\python.exe`）。依赖包：`pymupdf ezdxf rapidocr-onnxruntime olefile Pillow`，建议加 `pypdfium2`（PDF 渲染兜底，约 3MB）。
